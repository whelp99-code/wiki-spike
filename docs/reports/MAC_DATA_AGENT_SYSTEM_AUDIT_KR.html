운영 원칙: Canary/runner 및 활성 PID는 증거와 허용목록을 확보한 뒤에만 다룹니다. 멈출 수 있는 대상은 “오래됨”이 아니라 명백히 stale임이 입증된 cron 또는 MCP에 한정합니다.

우선순위 위험

1. Docker 제어면 실패 + stale secret-probe cron

Docker API가 응답하지 않습니다. Sangfor 관련 cron/docker exec 4개는 약 7시간 동안 redacted JWT keyring 환경 변수를 질의하며 정체되어 있습니다. 값은 읽지 않았습니다.

2. 공개 full-write 터널

cloudflared가 로컬 7979을 공개 경계로 연결하며 full-write 프리셋이 설정되어 있습니다. 인증이 확인되지 않았습니다.

3. MCP fanout·수명 관리

774개 MCP 프로세스가 약 4.8 GiB를 사용합니다. 반복 기동, 세션 TTL 부재, 고아 프로세스 가능성이 비용과 장애 범위를 키웁니다.

4. 와일드카드 포트와 권한 경계

Sangfor PG/web와 unified-db가 와일드카드로 게시되어 있습니다. 여러 Codex/Claude 프로세스는 승인 또는 권한 우회 모드이며, ~/.codex·~/.claude·~/.gjc는 0755입니다(Orca 루트는 0700).

5. 백업·정비 실패

백업 에이전트의 최근 종료 코드는 70, memory-router maintenance의 최근 종료 코드는 1입니다. Time Machine 대상도 관측되지 않았습니다.

6. 저장소 압박

System Data가 91% 사용 중입니다. Docker.raw의 논리 크기와 다수의 에이전트 캐시가 회복·업데이트·로그 보존의 여유를 제한할 수 있습니다.

개선 로드맵

  • Canary/runner를 포함한 활성 PID 증거와 허용목록을 작성
  • 입증된 stale cron/MCP만 중지
  • Docker 제어면을 안전하게 복구하고 터널 인증을 감사
  • DB 포트를 localhost 바인딩으로 전환

1–7일 · 실행 수명과 회복성

  • MCP supervisor·공유 pool·세션 TTL 도입
  • printenv 기반 secret probe를 제거하고 마운트 자격증명 또는 내부 API 사용
  • health check·경보·백업 검증 추가

8–30일 · 정책과 복구 훈련

  • 중앙 저장소 정책, 보존 quota, 로그 회전 적용
  • 최소 권한 에이전트 프로필과 네트워크 세분화
  • 정기 restore drill로 복구 가능성을 검증
